# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` L73-74 | Does not actually ping MongoDB; always returns `{"status": "ok"}` even when the database is down. The grader polls this before testing. | Start the server with no MongoDB running — health still returns 200 instead of 503. | Wrapped `db.command("ping")` in a try/except; return 503 on failure. |
| 2 | `create_employee()` L79-80 | Race condition: uses check-then-insert (`find_one` then `insert_one`). Two concurrent requests with the same `emp_code` can both pass the check and both insert. | Send two POST `/employees` requests with the same `emp_code` at the same instant — both get 201. | Created a unique index on `emp_code` and catch `DuplicateKeyError` instead of pre-checking. |
| 3 | `create_employee()` L82 | `datetime.now()` returns a naive datetime (no timezone). MongoDB stores it as-is, and the API may return the wrong epoch-ms value. | Compare `created_at` between servers in different timezones — values differ. | Changed to `datetime.now(timezone.utc)`. |
| 4 | `create_employee()` L85 | Returns the raw MongoDB document (with raw `datetime` objects) instead of serializing `created_at` to epoch milliseconds. | Response body contains a datetime string instead of an integer for `created_at`. | Used `_serialize_employee()` to convert datetimes to epoch-ms. |
| 5 | `create_employee()` | Missing validation: `shift_start` must differ from `shift_end` (per openapi.yaml). | POST an employee with `shift_start == shift_end` — accepted when it should be 422. | Added explicit check before insert. |
| 6 | `list_employees()` L93 | Wrong skip calculation: `skip = page * page_size` instead of `(page - 1) * page_size`. Page 1 skips the first `page_size` records. | GET `/employees?page=1` returns page 2's data; page 1's data is unreachable. | Changed to `skip = (page - 1) * page_size`. |
| 7 | `list_employees()` L94 | `total` counts `db.employees.count_documents({})` ignoring the `department` filter, so the pagination metadata is wrong when filtering. | GET `/employees?department=Engineering` — `total` reflects all employees, not just Engineering. | Changed to `count_documents(q)` using the same filter. |
| 8 | `list_employees()` L95 | Missing sort: the spec requires sorting by `emp_code` ascending. Results come in insertion order. | Insert employees out of order — listing returns them unsorted. | Added `.sort("emp_code", ASCENDING)`. |
| 9 | `list_employees()` | Response does not serialize `created_at` to epoch milliseconds. | `created_at` in the response is a raw datetime string or missing. | Used `_serialize_employee()` for each item. |
| 10 | `punch_in()` L102 | `datetime.fromtimestamp()` returns a naive local-time datetime, not UTC. All subsequent calculations are off by the server's UTC offset. | Run on a server in IST — all punch times are stored 5.5 hours ahead of the correct UTC value. | Used `datetime.fromtimestamp(ms / 1000, tz=timezone.utc)`. |
| 11 | `punch_in()` L102 | No truncation to whole seconds per R1: microseconds from the epoch-ms conversion are kept. | Punch in at a millisecond like `...999` — the stored timestamp includes sub-second precision affecting late/overtime calculations. | Applied `_truncate_to_seconds()`. |
| 12 | `punch_in()` L103 | Attendance date is always `ts.date()` (server-local or UTC date) instead of the IST calendar date per R1. Overnight shifts are not handled. | An overnight-shift employee punches in at 23:30 IST (which is 18:00 UTC) — date is wrong. | Implemented `_compute_attendance_date()` with IST conversion and overnight-shift logic. |
| 13 | `punch_in()` L101-104 | Race condition: uses check-then-insert (`find_one` then `insert_one`). Two identical punch-ins at the same moment can both succeed. | Send two concurrent POST `/attendance/punch-in` for the same employee — both get 201. | Created a unique compound index on `(emp_code, date)` and catch `DuplicateKeyError`. |
| 14 | `punch_in()` | Does not validate that the employee exists (no 404 if `emp` is None) — `emp["shift_start"]` would crash with a `TypeError`. | Punch in with a non-existent `emp_code` — unhandled 500 error instead of 404. | Added explicit 404 check before using `emp`. |
| 15 | `punch_in()` | Does not validate `punched_at` range (must be ≥ 100000000000). Seconds-scale timestamps or negative values are accepted. | Send `punched_at: 1609459200` (seconds, not ms) — accepted, produces a date in 1970. | Added `_validate_epoch_ms()` with range checking. |
| 16 | `punch_in()` L119 | Returns `doc["id"] = str(res.inserted_id)` — the `id` field should not be in the response (no `_id` in the API contract). | Response body contains an extra `id` field. | Removed `id` from the response; used `_serialize_attendance()`. |
| 17 | `compute_late_minutes()` L35 | `punch_in.replace(hour=h, ...)` uses the raw (UTC or local) datetime instead of converting to IST first. Late calculation is wrong for any timezone offset. | Employee with 09:30 shift punches in at 04:05 UTC (09:35 IST) — function computes late based on UTC hour 4, not IST hour 9. | Converted `punch_in` to IST before comparing against `shift_start`. |
| 18 | `compute_late_minutes()` L37 | Returns `minutes` (not `int(minutes)`) which can be a float since `total_seconds()` may have sub-second residue. Spec says `late_minutes` is an integer. | Float value like `10.5` stored instead of `10`. | Used `int(diff_seconds // 60)` (floor). |
| 19 | `compute_work_hours()` L41 | Uses Python's built-in `round()` which is banker's rounding (round-half-to-even), not half-up. R4 requires half-up. | `round(8.005, 2)` → `8.0` instead of `8.01`. | Used `Decimal.quantize(ROUND_HALF_UP)`. |
| 20 | `compute_overtime()` L46 | Constructs `end` from `date_str` without accounting for overnight shifts (shift_end falls on the next calendar day). | Overnight shift 22:00-06:00 on date 2026-07-06: `end` is 06:00 on the 6th instead of the 7th — overtime is massively wrong. | Added logic: if `shift_end <= shift_start`, add one day to the end datetime. |
| 21 | `compute_overtime()` L47 | No 30-minute minimum threshold: returns any positive overtime. R3 says overtime counts only when ≥ 30 minutes. | Employee leaves 15 minutes after shift end — `overtime_minutes` is 15 instead of 0. | Added `return minutes if minutes >= 30 else 0`. |
| 22 | `list_attendance()` L144-146 | Loads the **entire** collection into memory (`list(db.attendance_logs.find(q))`) and sorts in Python. With ~100k records this is slow and memory-heavy. | On the grader's 100k-record dataset: high memory usage, slow response, possibly OOM. | Used MongoDB `.sort().skip().limit()` with proper indexes. |
| 23 | `list_attendance()` L149 | Returns `id` (stringified `_id`) in the response — `_id` must never appear in the API. | Response contains an `id` field not in the contract. | Excluded `_id` from the query projection; used `_serialize_attendance()`. |
| 24 | `list_attendance()` | Missing validation: `date_from > date_to` should be 422. | Send `date_from=2026-08-01&date_to=2026-07-01` — silently returns 0 results instead of 422. | Added explicit check. |
| 25 | `list_attendance()` | Missing `_serialize_attendance()`: punch times are returned as raw datetimes instead of epoch milliseconds. | `punch_in`/`punch_out` in the response are datetime strings or objects instead of integers. | Applied `_serialize_attendance()` to each item. |

Also noted things that are **not** defects:
- The `IST = timezone(timedelta(hours=5, minutes=30))` constant is correct (UTC+05:30).
- Using `pymongo` directly (not Motor) is fine for this sync FastAPI app.
- The `load_dotenv()` at module level is correct behavior per the spec.
